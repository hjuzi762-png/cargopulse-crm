# CargoPulse CRM

面向国际货代销售团队的客户跟进与 KPI 管理 Demo。

在线演示：

- GitHub Pages: https://hjuzi762-png.github.io/cargopulse-crm/
- 备用 Demo: https://cargopulse-crm-demo.hjuzi762.chatgpt.site

## 题目对应

本项目选择 WallTech 产品面试题中的 AI Coding 方向：为 CRM 增加客户跟进事件能力，并围绕客户详情、跟进历史、活动类型和销售 KPI 做一个可运行原型。

我把题目拆成三个核心问题：

- 销售如何快速知道哪些客户今天必须跟进？
- 客户沟通过程如何沉淀为可交接、可追溯的时间线？
- 管理者如何从跟进记录得到可信的团队行动指标？

## 核心功能

- 客户列表：支持搜索客户、联系人和航线，支持全部、重点、待跟进、风险客户筛选。
- 客户详情：展示联系人、电话、阶段、下次行动、航线、月货量、商机金额、报价有效期和账期。
- 新建/编辑客户：支持录入与修改客户基础信息，并校验电话、同名客户、过去日期和报价有效期。
- 跟进时间线：记录电话、会议、拜访、邮件、微信等跟进方式，沉淀沟通内容、客户意向和下一步行动。
- AI 辅助整理：在新增跟进时模拟识别客户需求、风险和行动建议；保存前仍需人工确认，避免 AI 直接污染客户档案。
- 团队看板：统计最近 7 天跟进趋势、跟进方式分布、按时完成率、客户覆盖率和行动计划率。
- KPI 追溯：KPI 口径可查看，风险/逾期行动可点击跳转回客户，避免指标只停留在展示层。
- 本地保存：使用浏览器 localStorage 保存演示数据，支持恢复初始演示数据。

## 产品设计取舍

这个 Demo 没有做成静态页面，而是优先做成能操作的销售工作台。第一屏直接展示客户、指标和待处理事项，便于面试官快速验证功能。

产品边界上，当前版本更像“前端高保真可运行原型”，不是完整生产 CRM。生产版本还需要补充：

- 登录与销售角色权限
- 后端数据库和多人协作
- 客户、跟进、任务的审计日志
- 真实 AI 接口、置信度、采纳/驳回记录
- 更完整的导出、导入和企业微信/邮件集成

## 技术说明

项目使用原生 HTML、CSS 和 JavaScript 实现，不依赖构建工具。这样做的原因是面试题重点在产品逻辑、交互闭环和 AI 辅助流程，而不是复杂工程框架。

直接打开 `index.html` 即可运行；部署到 GitHub Pages 时选择 `main / root`。

## 演示建议

建议按以下顺序演示，控制在 6 到 8 分钟：

1. 先说明业务痛点：货代销售跟进散落、客户状态不透明、主管 KPI 难追溯。
2. 演示客户列表：搜索、筛选重点客户、待跟进和风险客户。
3. 打开客户详情：讲清楚为什么加入航线、月货量、商机金额、报价有效期、账期。
4. 新增一条跟进：展示 AI 辅助整理，但强调人工确认后才入库。
5. 编辑客户：说明真实 CRM 必须允许修正客户信息，避免数据质量长期污染。
6. 切到团队看板：展示 KPI 口径，并点击风险行动回到客户详情。
7. 最后说明边界和生产化路线：后端、权限、审计日志、真实 AI 接口和企业系统集成。
